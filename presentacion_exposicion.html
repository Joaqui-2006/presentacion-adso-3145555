Plan B (Lava Rápido): README del Backend Vacío

Un monolito modular en Spring Boot (15 módulos) cuyo README.md solo tiene una línea: # backend.

🔴 El Problema (Evidencia: README.md:1)

# backend
  • Cero instrucciones de arranque: No explica que requiere JDK 17, PostgreSQL con el esquema previo (ddl-auto=validate) ni cómo correr Docker.
  • Variables secretas/críticas sin documentar (H-20): .env.example omite variables que exige docker-compose.yml (WOMPI_PUBLIC_KEY, MAIL_*, CORS_ALLOWED_ORIGINS).
  • Regla oculta de Administradores (H-06): AdminIdentityPolicy.java:21 exige exactamente 2 UUIDs en ADMIN_USER_IDS creados con una herramienta CLI interna (OwnerProvisioningTool.java) que nadie documentó.

🟢 La Solución (Reescritura de README.md)

# Lava Rápido Vehicular — Backend API (Spring Boot 3 / Java 17)
## 1. Requisitos y Arquitectura (15 módulos)
- JDK 17, Maven (./mvnw), Docker y PostgreSQL 16.
## 2. Variables de Entorno (.env)
- DB_URL, DB_USERNAME, DB_PASSWORD, JWT_SECRET
- WOMPI_PUBLIC_KEY, WOMPI_PRIVATE_KEY, WOMPI_EVENTS_SECRET
- ADMIN_USER_IDS (2 UUIDs separados por coma)
## 3. Orden de Arranque
1. Levantar BD y migraciones SQL
2. cp backend-vehicular/.env.example backend-vehicular/.env
3. docker compose up --build
## 4. Aprovisionar Primer Administrador
./mvnw exec:java -Dexec.mainClass="...OwnerProvisioningTool"

Criterio de cierre: Un tercero levanta el backend en una máquina limpia siguiendo solo el README.md.

Plan C (SmartHome): Ruta Inexistente al Salir del Hogar

Doble ruptura de contrato REST (Método HTTP + URL) entre la App Móvil (from_movil) y el Backend (smarthome-backend).

🔴 El Problema (Error 404 Not Found)

1. Lo que envía la App Móvil (lib/services/smart-home-service.ts:217):

// ❌ Método POST y ruta sin /members/me
leaveHome(homeId, token) {
  return apiClient.post<void>(
    `/api/v1/homes/${encodeURIComponent(homeId)}/leave`,
    undefined,
    { token },
  );
}

2. Lo que espera el Backend NestJS (homes.controller.ts:182):

// ✅ Método PATCH y sub-recurso /members/me/leave
@Patch(':homeId/members/me/leave')
@UseGuards(JwtAuthGuard)
async leaveHome(@CurrentUser() user, @Param('homeId') homeId: string) {
  return this.leaveHomeUseCase.execute(user.userId, homeId);
}

🟢 La Solución (Alinear Contrato REST + OpenAPI)

1. Corregir línea 216-217 en smart-home-service.ts:

// ✅ Cambia .post -> .patch y ajusta el path exacto
leaveHome(homeId, token) {
  return apiClient.patch<void>(
    `/api/v1/homes/${encodeURIComponent(homeId)}/members/me/leave`,
    undefined,
    { token },
  );
}
  • 2. Documentar en Swagger (H-42): Añadir @ApiOperation({ summary: 'Abandonar hogar' }) en homes.controller.ts:182.
  • 3. Test de Contrato: Añadir prueba unitaria verificando método PATCH y ruta /members/me/leave.
  • Criterio de cierre: El botón "Salir del hogar" responde 200 OK y retira al miembro del hogar.
